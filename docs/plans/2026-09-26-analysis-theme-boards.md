# 主题分析看板实施计划

目标：将分析页默认入口改为主题组合看板，保留左侧条件、真实数据及所有单项分析入口。宽屏一主两辅，窄屏顺序排列；可放大任意图并返回同组。默认主题为变化规律，另有变量关系与空间诊断。

架构：`AnalysisDock` 管理组合/单项入口；新 `AnalysisBoard` 负责三图布局、单图放大和 Plotly 主题。两颗星球分别生成 `{ panels, note }`，面板结构为 `{ id, title, data, layout, empty? }`，`data` 为 Plotly trace 列表，`layout` 仅携带各图的坐标/单位等语义。Earth 复用 controller 的年度与空间数据，Mars 请求当前主题所需的真实热力图并拒绝过期回包。旧单项组件和 AI 入口继续通过单项分析访问。

实现范围：

- [x] Earth：新增 `EarthOverview/earthAnalysisBoardModel.js` 与测试。季节矩阵、所选变量原始全球均值、纬带振幅；关系使用后端关系模型与有限值标准化曲线；空间使用后端距平和 RMS/跨度。保持 ISO 日期、DU 与面积加权统计。
- [x] Mars：新增 `OverviewCharts/marsAnalysisBoardModel.js` 与测试。从真实热力图生成季节矩阵、均值曲线、纬带振幅；按共同 Ls 对齐关系样本，缺失值不补零；空间诊断保持纬向距平。单位换算区分温度值和温差。
- [x] 共用展示：新增 `workbench/AnalysisBoard.jsx`、样式和页面级状态；修改 `AnalysisDock.jsx` 加入组合/单项切换。面板放大保留筛选并提供返回；双语言、键盘、深浅主题、窄屏都可用。
- [x] Mars：新增主题请求组件和左栏条件，使用独立主题条件键；保留既有单图条件。失败可重试，空数据单独显示，切换后忽略旧结果。
- [x] Earth：接入 controller 按当前主题加载一份年度/空间数据；主题变量关系只提供后端支持的温度与辐射变量，范围保留纬带。保留全部单项和能力说明。
- [x] 检查所有主题、变量、年份、详情入口、面板放大返回及失败恢复；执行 Node 全套测试和生产构建，重启前端并验证三项 HTTP 状态。
- [x] 同步 README 与工作台文档，记录实现边界和验证证据。

验证：新增模型测试先红后绿，重点验证原始数值不被改变、null 不变成 0、时间轴正确对齐、温差不减 273.15、输入不被修改。浏览器对两星球三主题逐项操作，检查桌面中文深色、英文浅色和 120% 字体，以及模拟 503/延迟旧请求。用户随后明确桌面为主战场，后续调整与验收聚焦桌面，不继续手机或平板专项适配。

边界：本轮不承诺跨图刷选、自由拖动卡片或跨星球比较。保留单项分析的 AI 解读；组合看板仅展示有实际数据依据的图，不伪造综合 AI 结论。工作区既有修改原位保留，不提交、不重置、不批量删除。
